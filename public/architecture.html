Key Process Flows
Upload Flow
1
Officer selects file and fills evidence form inside a case
2
Server checks officer is assigned to the case
3
File saved to disk via multer
4
SHA-256 hash generated from file stream
5
Hash stored on blockchain via storeHash()
6
Evidence metadata saved to MongoDB (hash NOT included)
7
Custody chain entry + ActivityLog created
Verification Flow
1
Officer clicks Verify on any evidence item
2
Server re-generates SHA-256 hash of current file on disk
3
Original hash fetched from blockchain via getHash()
4
Hashes compared — match = Verified, mismatch = Tampered
5
verificationStatus updated in MongoDB
6
Result card shown with blockchain metadata
Access Control Flow
1
Officer logs in → JWT issued with officer ID
2
Every request passes through authMiddleware
3
Evidence/case queries filter by assignedOfficers array
4
Officer sees only their assigned cases and evidence
5
Admin token has isAdmin: true → bypasses all filters
6
Admin sees all officers, cases, evidence, activity
